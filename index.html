Ou connecter Kraken avec une clé API en lecture seule

GitHub Pages ne peut pas appeler l’API privée Kraken directement. Lancez npm run connect sur votre ordinateur puis ouvrez son adresse locale, ou autorisez explicitement l’origine de votre site dans le connecteur. La mémorisation des clés est facultative et locale.

Créez une clé dédiée avec uniquement Data → Query ledger entries et Funds → Query funds. Ne cochez aucune autorisation de trading, dépôt, retrait, transfert ou Earn. Une clé API comporte une clé publique et un secret. Ne partagez jamais le secret et ne le placez pas dans le dépôt GitHub.

Clé publique et secret stockés chiffrés dans ce profil navigateur. Jamais le code 2FA. Tout script de la même origine peut réutiliser la clé mémorisée : ne cochez cette option que sur votre appareil personnel et un site de confiance.

Les identifiants ne sont pas mémorisés par défaut.

Limite API : les valorisations historiques USD du CSV ne sont pas fournies par l’API. Les coûts des échanges simples avec USD sont reconstruits ; les autres coûts d’achat et produits de vente restent inconnus. Les distributions explicitement identifiées ont un coût économique nul, mais leur valeur à réception reste inconnue. Pour vos achats en EUR notamment, préférez le CSV avec valeurs USD. Les quantités sont rapprochées des soldes API. Actualisez ou saisissez les cours pour valoriser les actifs détenus.

La lecture intégrale peut prendre plusieurs minutes (pagination de 50 lignes, limite de 10 000 écritures). Seules les données complètes sont chargées.

Une sortie « hybridearnwithdrawal » du portefeuille Spot n’est pas forcément une vente ou une sortie de votre patrimoine. Le site conserve le capital transféré et son coût, puis déduit les retours « hybridearndeposit ». Cette position est une reconstitution, pas un solde actuel confirmé : rendements, pertes et opérations hors ledger ne sont pas connus. Vérifiez le solde de votre coffre. Décochez si vous ne détenez plus ces fonds ou si votre solde API inclut déjà ce produit, pour éviter un double comptage.

Facultatif : coût unitaire estimé des soldes initiaux et apports inconnus d’un actif, dans la devise d’affichage (conversion en USD au taux indiqué). Dans le mode de référence, cela complète aussi les distributions sans valeur à réception. Ce n’est pas le coût des achats du CSV.

Ces hypothèses sont appliquées au fil de l’historique, y compris aux unités déjà vendues. Les distributions explicitement gratuites gardent toujours un coût économique nul. Les autres coûts renseignés restent des estimations. Effacez une valeur pour revenir au coût inconnu.

    Comprendre les calculs et leurs limites

    Devise : USD. Les valeurs historiques viennent de amountusd, feeusd et balanceusd. Les monnaies fiat sont exclues des gains crypto. Les stablecoins sont inclus.

    Achats et ventes : les lignes sont regroupées par refid. Le coût d’achat inclut les frais payés en fiat sur la sortie ; les frais prélevés sur l’actif reçu réduisent sa quantité. Une vente retire une part proportionnelle du coût moyen. Une conversion crypto → crypto est une cession puis une acquisition : les frais en crypto sortants retirent du coût dans le gain réalisé et ne sont pas ajoutés au coût du nouvel actif ; les frais en crypto reçue réduisent sa quantité sans être aussi soustraits du produit de cession. Chaque frais est ainsi pris en compte une seule fois. Les conversions de poussières répartissent le produit selon les valeurs USD des actifs cédés.

    Earn, bonus et airdrops : deux conventions sont disponibles. Le mode économique, activé par défaut, attribue un coût d’acquisition nul aux distributions explicitement identifiées : toute leur valeur encore détenue contribue au non réalisé, et leur produit net de vente au réalisé, même après une baisse du cours. Le mode de référence les capitalise à leur valeur nette à réception et mesure la variation ultérieure. Une valeur USD à réception manquante ne rend pas leur coût économique inconnu, mais leur revenu historique et leur gain de référence restent partiels. La valeur à réception affichée séparément ne doit jamais être ajoutée une seconde fois aux gains économiques.

    Mouvements : les transferts appariés d’un même actif sont neutres. Les quantités et coûts payés/gratuits/inconnus sont retirés proportionnellement à chaque sortie. Une conversion réalise le gain de l’actif offert cédé ; l’actif acquis reçoit le coût de l’échange, évitant de compter de nouveau le même bonus. Un retrait externe retire quantité et coût, sans créer une vente. Les avoirs hors Kraken et les positions Futures ne sont pas suivis.

    Historique incomplet : les soldes précédant la première ligne de chaque portefeuille sont reconstitués à partir du solde, du montant et des frais. Leur coût, et celui des dépôts externes, reste inconnu. Les sorties retirent proportionnellement des unités connues et inconnues. Le gain global est partiel tant qu’il manque des coûts ou des prix. Le coût estimé facultatif concerne tous les apports inconnus d’un actif.

    Prix : par défaut, dernier prix implicite disponible pour chaque actif dans le CSV, à une date potentiellement différente. Ce n’est pas un instantané actuel du portefeuille. L’actualisation facultative utilise le dernier échange des paires USD de l’API publique Kraken ; les actifs sans paire conservent leur ancien prix. Les prix manuels permettent de valoriser les autres actifs.

    Confidentialité : aucune sauvegarde automatique des opérations, aucun cookie et aucune télémétrie. Recharger la page efface les données de portefeuille. L’actualisation des cours contacte l’API publique Kraken avec les symboles demandés, jamais les transactions ni les soldes. En mode clé API, votre connecteur local contacte les endpoints privés de lecture Kraken ; le secret sert uniquement à signer les requêtes. La case facultative « Mémoriser » conserve la clé et le secret chiffrés dans ce navigateur, jamais le code 2FA. Le bouton « Oublier » supprime cette copie locale ; pour révoquer la clé, utilisez Kraken. Aucun identifiant n’est envoyé au serveur GitHub Pages.

    Outil indicatif, pas un calcul fiscal ni un conseil financier. Calculs en nombres JavaScript : de petits écarts d’arrondi sont possibles.
